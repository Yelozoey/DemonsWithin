# 《心魔》同局 LLM 战术

## 连接和试玩

1. 在 **Tools → Demons Within → LLM 战术** 填写兼容 Chat Completions 的完整请求地址和模型名。Ollama 本地默认地址为 `http://127.0.0.1:11434/v1/chat/completions`，模型名填写服务已加载的名称。云服务使用 HTTPS，如需鉴权，填写 Unity 进程能读取的密钥环境变量名。接口不支持 `response_format` 时可关闭 JSON 模式，模型仍需按提示返回 JSON。[Ollama 兼容接口](https://docs.ollama.com/api/openai-compatibility) · [llama.cpp Server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)
2. 点击「测试连接」再保存。配置存入本机 `Application.persistentDataPath/llm-tactics.json`。保存后切到 LLM 模式重新加载设置。Unity 编辑器与开发构建可以走本地 HTTP，发布构建使用 HTTPS。[Unity HTTP 配置](https://docs.unity3d.com/cn/6000.0/ScriptReference/InsecureHttpOption.DevelopmentOnly.html)
3. 在 `PhaseOneArena` 进入 Play。**F2** 按「本局自适应 → 固定 → LLM」循环。默认本局自适应，切到 LLM 后才会发送战术请求。**F1** 显示战术状态，行为树参数区也能看到最近一次出招及战术。**F3** 导出记录，**R** 重开并保留当前模式。

## 感知、推理和执行

战斗按固定步持续观测。挥击结算后，本地对手模型立刻更新，LLM 队列则保留最近 12 个有效交手。首次积累 3 个有效交手后可以请求，后续每次至少新增 2 个有效交手，并遵守最短请求间隔。请求只包含交手编号、心魔招式、距离段、玩家可见反应和结算结果。接入云服务时，这些交手摘要会发送给所填地址。

LLM 在对局期间异步选择一次战术。每局最多同时等一个回复，默认请求时限 3 秒、最短请求间隔 1.5 秒。它可以建议继续观察，也可以建议延迟击、突刺或快击，需给出请求快照里两条方向一致的证据。分别针对快击后的早弹、持续后撤、主动抢攻或逼近。Unity 验证战术、证据、适用距离和 1 至 2 次试探预算。等待期间如果已新增超过 4 条有效交手，回复会因证据过期被弃用。

待执行战术默认有效 8 秒。行为树在距离、冷却和状态均允许时选择招式，战斗状态机实际启动动作后才消耗一次。保留原有的固定基线探测。两次相同起手条件下的后续反应推翻原模式，或试探被弹反、识破、闪避时，剩余试探会撤销。没到适用距离、无可用战术、连接失败或超时时，心魔用本地适应继续对战。结束、重开、切出模式都会取消正在等待的请求。

## 对比记录

F3 导出 schema 2。用 `llm` 中的 `requestId` 对应交手里的 `planId`。收到有效回复时记录采纳延迟、适用距离和证据编号，实战启动时记录从请求到出手的毫秒数。也可检查落空、被反制、预算耗尽、超时和撤销原因。

灰盒对比可重复做快击起手早弹、反复后撤、以及中途改成晚弹三组脚本。固定、本局自适应和 LLM 组都从重开开始。用采纳后实际启动过的战术编号占比、请求至第一次出手的耗时，以及变招后旧战术停止所需的有效交手数比较三组。记录里的 `baselineAttack` 与 `chosenAttack` 可用于判断实际出招是否发生变化。
