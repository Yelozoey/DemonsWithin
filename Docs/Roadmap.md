# 《心魔》分阶段开发计划

2026-11-22 · Unity `6000.6.8f1` · URP `17.6.0`

本计划延续[开发文档](Development.md)。先做能反复交手的固定对手，验证战斗手感和有效应对窗口，再用同一套规则对比本地适应和 LLM 战术。各阶段都可以接收美术、场景、角色和音效。

## 阶段与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1 · 灰盒对决 | 单场地、第三人称锁定镜头、移动、固定优先级对手、快击／延迟击／突刺、格挡／弹反／识破／闪避、胜负和重开 | 相同距离和时机得到可复现的判定。可从前兆区分三种攻击，防御成功与失败有可读反馈 |
| 2 · 对局记录与在线适应 | 记录战斗步、实际可选择的机会、玩家公开动作、AI 出招及结果。用带衰减的条件频率更新招式权重 | 用早弹、持续后撤和中途变招三类脚本跑对局。比较被针对前后的选招，检查旧权重能否随变招回落 |
| 3 · 同局 LLM 战术 | 异步提交证据快照，模型从已有战术里选择试探。校验结果并在合法出招点写入行为树 | 比较固定 AI、本地适应和 LLM 三组。记录战术采纳率、请求到生效时间、失效条件和实际出招，模拟延迟、超时和重开 |
| 4 · 手感与内容迭代 | 接入正式或阶段性角色、场景、武器、音效和特效，按动作接触点校准表现 | 真人盲测能描述心魔在针对什么，并通过变招重新占优。替换素材后回归判定、前兆、镜头、可读性和帧率 |

## 素材接入点

- **角色和动画。** 玩家和心魔各有可替换的角色预制体。模型骨架、Animancer 片段和阵营材质放在表现层，由战斗状态机决定动作与时序。换角色时先校验 Avatar、体型与碰撞体，再调整接触姿势与动画播放速率。需要改判定窗口时在招式数据中单独调整并复测。
- **场景。** 保留对局控制器、相机、两个出生点和可行走碰撞。可以在灰盒上替换几何和灯光，也可以把战斗组件迁入新的场景，再验证场地边界、遮挡和锁定镜头。
- **音效和特效。** 以可读前兆、出手、命中、格挡、弹反、识破和闪避结果为接入点。阶段 1 用颜色和 HUD 验证时序，接入具体音效或特效时再为这些时点绑定表现。
- **资源目录。** 可直接替换或复制 `Assets/DemonsWithin/` 下的场景、预制体和材质。Lucy 和 Animancer 保留在各自的导入目录，项目自有逻辑集中在 `Assets/DemonsWithin/Runtime/`。

## 第一阶段游玩

第一阶段的灰盒原型已生成。Unity Play Mode 已验证动画循环、移动、距离判定、一次命中、格挡、弹反时机、识破、闪避与重开。正式动作、音效和真人手感评估仍可在后续迭代中接入。

打开 `Assets/DemonsWithin/Scenes/PhaseOneArena.unity` 后进入 Play。WASD 奔跑，中键锁定对手，Ctrl 走路，Shift + 方向键冲刺，空格闪避。新版操作、连招窗口、动画过渡与动作时间轴见[移动与动作编辑](CombatAuthoring.md)。

## 第二阶段游玩

心魔默认根据当前对局的早弹和后撤习惯调节选招。F1 查看证据与出招原因，F2 循环切换对手模式，F3 导出本局记录。统计规则、试打方法和日志字段见[同局对手建模与交手记录](OpponentAdaptation.md)。

## 第三阶段游玩

灰盒场景已接入同局 LLM 战术。可在 Unity 的 LLM 战术窗口配置模型服务，再用 F2 切到 LLM 模式。连接方式、请求节奏、战术失效规则及实验字段见[同局 LLM 战术](LlmTactics.md)。本地模拟服务覆盖了请求、校验、出手、超时和重开。真实模型的响应时间与三组对战对比仍待联调。
