# 《心魔》开发文档

2026-11-22 · 立项与原型设计

《心魔》（DemonsWithin）是一款第三人称单人对战游戏。玩家在小型场地里与一个由 LLM 参与战术决策的心魔交手，使用攻击、格挡、弹反、闪避和识破等机制。心魔持续观察玩家的打法，在同一场对决中逐渐针对反复出现的习惯。玩家可以通过改变出手节奏、距离或防守选择来拆解它的应对。

阶段划分与素材接入见[分阶段开发计划](Roadmap.md)。新版操作和编辑工具见[移动与动作编辑](CombatAuthoring.md)，第二阶段实装见[同局对手建模与交手记录](OpponentAdaptation.md)。

## 工程与首版范围

- 编辑器版本为 `6000.6.8f1`。工程使用官方 Universal 3D 模板，URP 包版本为 `17.6.0`。检出与导入步骤见[项目说明](../README.md)。
- 首版只做一个灰盒擂台、一个玩家角色、一个心魔和一套武器。第三人称锁定镜头下验证快斩、延迟斩、可识破的突刺，以及弹反和闪避。
- 首版验证同局适应。灰盒场景已接入固定对手、本地建模、同局 LLM 战术与交手记录导出。运行方式见[同局 LLM 战术](LlmTactics.md)。跨局画像与正式模型部署留待后续验证。

## 战斗执行与战术更新

| 层 | 更新时机 | 职责 |
| --- | --- | --- |
| 战斗状态机 | 按战斗步推进 | 管理前摇、出手、后摇、受击、动作锁定和取消。碰撞、伤害、弹反与识破窗口由游戏代码判定 |
| 行为树 | 心魔可以作出新决策时 | 依据距离、朝向、动作状态和冷却筛选合法动作，再按默认权重、本地预测和当前战术选招 |
| 本地对手模型 | 每个可观察的决策机会结束后 | 更新玩家在相似情境下的动作分布，保存样本量、近期变化和预测结果 |
| LLM 战术规划 | 开局、出现新习惯、旧预测连续失准，或积累了足够新证据时 | 选择要针对的习惯和要试探的战术，给出适用情境、证据和撤销条件 |

战斗系统持续产生事件。本地模型处理完新的事件就更新统计，随后行为树可以在下一次合法的出招时机读取结果。LLM 在后台读取证据快照，分析接下来几次交手可以采取的策略。对局结束时生成可追溯的摘要，记录本局学到了什么、执行了哪些战术以及玩家如何应对。

## 观测、输入记录与玩家画像

以「玩家当时有机会选择」作为统计分母。面对一次可读的前摇，只有距离合理且玩家能自由行动时，才记录为一次有效应对机会。有效机会应包含主动等待等可选反应。硬直、动作锁定或尚未进入有效距离时，将无响应标为不可用。

| 记录 | 建议字段 |
| --- | --- |
| 原始输入 | 对局 ID、战斗步、输入动作、按下或松开、输入是否被缓冲或消费。供本地回放和调试 |
| 可观察交手 | 机会 ID、双方距离段、心魔当前起手和公开前兆、玩家最近公开动作、是否有应对机会、观察到的反应与相对时机、交手结果 |
| 玩家画像 | 情境、反应次数与有效机会数、近期和累计分布、支持及反驳该习惯的事件 ID |
| 心魔决策 | 已发布的战术、当时合法的招式、最终出招、是否命中或被拆解、被替换或撤销的原因 |

实时战术读取可观察事件和历史统计。原始按键缓冲留在调试链路中。心魔的即时反应从可见动作或公开前兆开始计时，按统一的反应延迟和招式规则执行。

本地统计从「对手起手 × 距离段」开始，并通过可行动状态筛选样本。使用近期窗口或衰减计数，让最近的变招逐步覆盖旧习惯。样本稀少时回退到更宽的情境或基线权重。动作顺序确实影响预测时，再加入前一个动作或短动作序列。记录心魔采取的招式，避免把某个试探造成的结果直接归因为玩家的全局习惯。

## LLM 与行为树的接口

请求包含对局 ID、证据快照版本、本局摘要、带样本量的近期统计、支持和反驳的交手片段、上次战术结果，以及可选战术目录。目录里的每项战术对应已经实现的动作及其适用条件。

响应使用结构化字段，包含战术 ID、适用情境 ID、证据 ID、最多尝试次数和撤销条件 ID。运行时校验枚举、数值范围、证据是否来自该次请求，以及对局是否仍有效。新一帧产生的数据可以继续进入统计。战术适用条件失效、相关证据被后续交手推翻或已有更新策略生效时，丢弃迟到结果。

同一时刻保留一个正在处理的请求，将积累的新证据合并到下一次请求。给请求设置冷却和超时，并给战术设置使用次数及时间有效期。校验通过后，由战斗主线程在下一个合法决策点更新行为树黑板。网络延迟期间使用当前有效战术。战术耗尽、失效或请求失败时，由本地预测和默认权重继续对战。

## 示例 早弹习惯与延迟斩

1. 玩家在近距离面对某种抬手时，8 次有效机会里有 6 次早弹。快斩和延迟斩采用可辨读的节奏，且两者都有合法防守窗口。
2. LLM 选择比较普通快斩和延迟斩。心魔在合适的距离与动作状态下尝试延迟斩，其选择在起手前确定。玩家仍可根据后续动作线索晚弹。
3. 本地模型记录两种起手下玩家的反应与结果。如果玩家开始稳定晚弹，心魔减少延迟斩。LLM 结合后续交手决定退回常规节奏，或选择另一个试探。
4. 该试探的有效反馈包括玩家识别并拆招，以及心魔据此减少针对。首版盲测关心玩家是否能说出自己哪条习惯被针对、哪次变招奏效。

## 原型顺序与验收

1. **固定行为树。** 先把锁定、移动、动作前后摇、碰撞和窗口做成可重复验证的对决。调试视图展示当前动作状态及防御窗口。
2. **本地在线适应。** 接入交手日志和条件频率表，让脚本玩家分别表现出早弹、反复后撤和中途变招。确认统计只在有效机会结算，权重会随新行为回落。
3. **LLM 策略接入。** 用同一套招式目录和战斗规则对比固定行为树、本地统计、以及加入 LLM 的版本。记录发现习惯需要的有效机会数、弃用旧战术需要的机会数、战术采纳率和从请求到生效的延迟。
4. **延迟测试与真人盲测。** 模拟正常、慢响应、超时和对局切换，验证此前请求的结果不会影响新对局。让真人切换打法，观察能否从动作节奏看出心魔在针对什么，并成功找到反制。

如果条件频率足以描述大部分模式，可以保留它作为运行时预测器。如果动作顺序成为主要信号，可尝试短序列模型。若需要在几个合法试探之间持续比较实际效果，可尝试带情境的多臂老虎机，并给高强度反制设置使用上限。若战斗能低成本推演未来一两招，再评估用对手预测引导 MCTS。用同一套脚本和盲测口径衡量每种方案的收益。
